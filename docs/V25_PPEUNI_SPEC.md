# v25 — 식단 운영 + 1·2차 준비 + 큐브 재고

작성 기준일: 2026-09-15

## 현재 결정

사용자 결정에 따라 **앱 기능 개발을 먼저 진행**한다.

『뿐이 토핑 이유식』은 최종 식단 기준이지만, 책에 일별 스케줄표가 없는 것으로 확인되어 현재는 앱 기능 검증용 임시 식단을 사용한다. 임시 식단은 절대로 『뿐이』 식단이라고 표시하지 않는다. 추후 사용자가 식단 기준을 정하거나 원문 스케줄표를 확보하면 식단 데이터만 교체한다.

## 핵심 기능

- 도준이 생년월일 2025-12-05 기준 월령 계산
- 일요일 1차 준비 → 월~목 4일치
- 목요일 2차 준비 → 금~일 3일치
- 배치별 준비 목록과 완료 체크
- 끼니별 식단 완료 체크
- 원물/토핑 큐브 제조 배치 재고
- 예: `A-1 / 양파 / 2026-09-01 / 20g × 20개`
- 완료 체크 시 사용 재고를 한 번만 차감
- 제조일이 오래된 배치부터 차감(FIFO)
- 다음 준비분을 사용한 뒤 임계치 이하가 예상되면 재제조 표시
- 기존 v24 데이터는 변경하지 않음

## 임시 식단 데이터

현재 개발 데이터는 `source: provisional`로 저장한다.

```json
{
  "source":"provisional",
  "sourceRef":"temporary:dev-plan:2026-09-14:breakfast",
  "title":"진밥 + 소고기 + 단호박 + 시금치 + 사과",
  "ingredients":[
    {"name":"진밥","grams":80},
    {"name":"소고기","grams":20},
    {"name":"단호박","grams":15},
    {"name":"시금치","grams":15},
    {"name":"사과","grams":20}
  ]
}
```

한 끼 개발 데이터는 총 150g으로 맞춘다. 이는 앱 기능 개발용 가안이며 『뿐이』 원문 식단이라는 의미가 아니다.

## 추후 『뿐이』 원문 데이터

실제 원문 식단을 확보한 항목은 다음처럼 구분한다.

```json
{
  "source":"ppeuni_verified",
  "sourceRef":"book-or-user-photo-reference",
  "title":"원문 식단명",
  "ingredients":[{"name":"양파","grams":20}]
}
```

`assertVerifiedMeal()`은 계속 `ppeuni_verified`만 허용한다. 임시 데이터는 개발 화면이 `allowProvisional: true`를 명시한 경우에만 사용할 수 있다.

## 큐브 재고 모델

```json
{
  "id":"A-1|양파|2026-09-01",
  "code":"A-1",
  "ingredient":"양파",
  "madeDate":"2026-09-01",
  "unitG":20,
  "initialCount":20,
  "remainingCount":20,
  "location":"냉동",
  "thresholdCount":4,
  "history":[]
}
```

동일 재료가 여러 제조 배치에 있으면 오래된 제조일부터 사용한다. 부족해도 음수 재고는 만들지 않고 부족 g을 별도로 남긴다.

## 데이터 키

v25 시험 화면은 기존 v24 저장값을 보존하기 위해 별도 키를 사용한다.

- `dj:prepCheck2`
- `dj:mealDone2`

기존 `settings2`, `foods2`, `shop2`, `inventory2`, `m2:*`는 변경하지 않는다.
