# v25 — 『뿐이 토핑 이유식』 고정 식단 + 배치 준비 + 큐브 재고

작성 기준일: 2026-09-15

## 1. 목적

도준이 밥상은 더 이상 앱이 임의로 만든 식단을 『뿐이 토핑 이유식』 식단처럼 취급하지 않는다.

도준이의 식단 자체는 **확인된 『뿐이 토핑 이유식』 원문 식단표**를 기준으로만 운영한다. 앱이 할 일은 그 식단을 바꾸는 것이 아니라 다음을 편하게 만드는 것이다.

- 도준이 생년월일(2025-12-05)에 따라 현재 월령/단계를 계산
- 일요일 1차 준비 → 월~목 4일치
- 목요일 2차 준비 → 금~일 3일치
- 준비 항목 완료 체크
- 끼니별 급여 완료 체크
- 미리 만든 원물/토핑 큐브 재고 관리
- 끼니 완료 시 사용 큐브 차감
- 재고가 떨어지기 전에 다음 준비일의 재제조 목록에 올림
- 기존 v24 데이터와 Firebase 가족 공유 데이터 보존

## 2. 식단 신뢰 원칙

1. `source === "ppeuni_verified"`이고 출처 식별자(`sourceRef`)가 있는 식단만 활성 식단으로 사용한다.
2. 저자/출판사 공개 식단표 또는 사용자가 보유한 책의 해당 식단표 페이지에서 실제 행을 확인한 뒤 입력한다.
3. 과거 ChatGPT가 생성한 30일 식단표, 임의 영양 조합, 랜덤 추천은 『뿐이』 식단 데이터로 승격하지 않는다.
4. 원문 행을 아직 확인하지 못한 날짜에는 임의 메뉴를 채우지 않고 `뿐이 식단 원문 확인 필요` 상태로 둔다.
5. 사용자의 최근 섭취 반응은 『뿐이』 식단 자체를 임의 변경하는 데 사용하지 않는다. 반응은 기록/관찰 자료로 유지하고, 식단 변경이 필요하면 사용자와 별도 결정한다.

## 5. 신규 데이터 모델

기존 v24 키는 삭제/변경하지 않는다.

### `ppeuniPlan2`
날짜별로 확인된 『뿐이』 식단만 저장한다.

```json
{
  "2026-09-14": {
    "breakfast": {
      "source": "ppeuni_verified",
      "sourceRef": "author-or-book-reference",
      "title": "원문에서 확인한 식단명",
      "ingredients": [
        {"name":"양파","grams":20}
      ]
    }
  }
}
```

### `cubeInventory2`
같은 재료도 제조일별 배치(batch)를 별도로 가진다.

예시:

```json
[
  {
    "id":"A-1|양파|2026-09-01",
    "code":"A-1",
    "ingredient":"양파",
    "madeDate":"2026-09-01",
    "unitG":20,
    "initialCount":20,
    "remainingCount":20,
    "location":"냉동",
    "thresholdCount":4,
    "history":[]
  }
]
```

화면 표시는 `A-1 양파 · 9/1 제조 · 20g × 20개 · 잔여 20개` 형태를 기본으로 한다.

### `prepCheck2`
배치별 준비 완료 체크를 저장한다.

### `mealDone2`
날짜+끼니 단위 완료 여부를 저장한다. 같은 끼니를 두 번 체크해도 재고가 두 번 차감되지 않아야 한다.

## 6. 재고 차감 및 재제조 규칙

- 동일 재료가 여러 제조 배치에 있으면 제조일이 오래된 것부터 사용(FIFO).
- 실제 식단의 재료 g을 큐브 단위 g으로 환산해 차감한다.
- 예: 양파 20g 큐브 20개 = 400g. 60g 사용 시 3개 차감 → 17개 잔여.
- 다음 1차/2차 준비분까지 사용한 뒤 남을 예상량이 임계치 이하라면 `재제조 필요`로 표시한다.
- 기본 재제조 임계치는 4개이며 재료별 수정 가능하게 한다.
- 재고가 없거나 부족하면 부족 g을 별도로 표시하고 음수 재고를 만들지 않는다.

## 7. 화면 요구사항

### 식단
- 현재 월령과 『뿐이』 단계 표시
- 각 끼니에 원문 확인 여부 표시
- 확인된 메뉴만 급여 완료 체크 가능
- 급여 완료 시 해당 재료 재고를 1회만 차감

### 준비
- `1차 준비 · 일요일 → 월~목`
- `2차 준비 · 목요일 → 금~일`
- 필요한 총 재료량
- 기존 큐브 재고로 충당되는 양
- 이번에 새로 만들어야 하는 양
- 재고 부족/재제조 예정 표시
- 각 준비 항목 체크박스

### 원물/큐브 재고
- 코드
- 재료명
- 제조일
- 1큐브 g
- 최초 개수
- 현재 잔여 개수
- 보관 위치
- 재제조 임계 개수
- 사용 이력

## 8. 기존 v24 보존

다음 기존 키와 기능은 파괴하지 않는다.

- `settings2`
- `foods2`
- `shop2`
- `inventory2`
- `avatar`
- `m2:*`
- 기존 offered/eaten 및 반응 기록

`inventory2`는 장보기용 현재 원물 재고로 남겨두고, `cubeInventory2`는 제조일과 개수까지 필요한 소분 큐브 재고로 별도 관리한다. 향후 사용성이 확인되면 통합 여부를 결정한다.

## 9. 가족 공유

v25 신규 키도 Firebase 가족 공유 대상에 추가해야 한다. 실제 부부 기기에서 검증하기 전에는 가족 공유 검증 완료로 보고하지 않는다.

동일 큐브 배치의 동시 수정 충돌을 줄이기 위해 최종 구현에서는 배치 단위 `updatedAt` 병합을 사용한다.

## 10. 완료 기준

- 도준이 2026-09-15 월령이 9개월/후기1로 계산된다.
- 9월 3주차가 1차 9/13→9/14~17, 2차 9/17→9/18~20으로 계산된다.
- 검증되지 않은 임의 식단은 strict validator에서 거부된다.
- `A-1 양파 / 9월 1일 / 20g×20개` 같은 제조 배치를 저장할 수 있다.
- 60g 사용 시 3개가 차감된다.
- 같은 끼니 완료를 두 번 눌러도 두 번 차감되지 않는다.
- 임계치 이하가 예상되면 재제조 필요가 표시된다.
- 정확한 『뿐이』 원문 식단 행이 없는 날짜에는 자동 생성 메뉴를 대신 넣지 않는다.
- 기존 v24 데이터는 그대로 읽을 수 있다.
- 브라우저 저장→재실행 및 두 기기 Firebase 공유는 별도 실사용 검증 결과를 남긴다.
